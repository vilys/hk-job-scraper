### 三個必須先知道的「情報反轉」

1. **Monster HK 已經不存在**。`monster.com.hk` 會 301 跳到 `www.foundit.hk`——Monster 亞太區已於 2022 年重整品牌為 **foundit**。所以「Monster HK 據點」的正確名字是 **foundit.hk**，對比表的記載已過時。
2. **獵聘與 BOSS直聘 的香港分站不存在**。對比表寫的 `liepin.com/hk` 與 `zhipin.com/hk` 都回 404。這兩站本質是**內地平台**，與「香港求職」的關聯薄弱，且 robots.txt **明文禁止**爬取搜尋結果。
3. ~~**HKGoodJobs 生死不明**~~ → **已更名為 OfferToday（情報反轉 #4）**。舊域 `hkgoodjobs.com`
   裸域、www、http、https、完整瀏覽器標頭**全部 403**，回應只有 202 bytes（連 robots.txt 都 403），
   且 TLS 憑證錯置錯誤網域 → 2026-09-05 判定「伺服器端全面拒絕」而止損。
   **2026-09-06 使用者提供新域：`https://www.offertoday.com/hk/recommend`**——
   站方應已轉址/更名，舊結論作廢，需以**低速、逐步**方式重新偵察（見 Wave 3′）。

## 一、分層策略與執行順序

按「可行性 × 香港職缺價值」排成五波，做穩一波再進下一波（沿用 plan.md 的開發建議第 1 條）。

### 🌊 Wave 1 — 低風險高回報（本地 HK 職缺主力）
| 順序 | 據點 | 預估難度 | 核心技術關卡 |
|------|------|----------|--------------|
| 1 | **Recruit** | 中 | ASP.NET WebForms 的 `__VIEWSTATE` / `__EVENTVALIDATION` 需先 GET 再 POST |
| 2 | **JobMarket** | 低–中 | 確認關鍵字搜尋網址；三層職能瀏覽網址已到手 |

### 🌊 Wave 2 — 需繞 WAF 或逆向 API
| 順序 | 據點 | 預估難度 | 核心技術關卡 |
|------|------|----------|--------------|
| 3 | **foundit.hk** | 中–高 | 搜尋頁被邊緣 WAF 擋（403）。**保底路線：sitemap**（已驗證可讀） |
| 4 | **eFinancialCareers HK** | 中–高 | 搜尋網址未知，需錄 XHR 找出 `/v1` API 或正確路徑 |

### 🌊 Wave 3 — 生死判定
| 順序 | 據點 | 預估難度 | 核心技術關卡 |
|------|------|----------|--------------|
| 5 | ~~**HKGoodJobs**~~ | 未知 | ~~先用一次 Playwright 判定生死~~ → **2026-09-05 判定舊域全面 403，已止損** |

### 🌊 Wave 3′ — 🔄 復活賽：OfferToday（原 HKGoodJobs 更名，2026-09-06 新增）
| 順序 | 據點 | 預估難度 | 核心技術關卡 |
|------|------|----------|--------------|
| 5′ | **OfferToday（www.offertoday.com/hk/recommend）** | 未知 | 逐層低速偵察：robots → 首頁 → 列表 → 卡片 → 翻頁 → 篩選 |

> 🐢 **本波強制節奏（使用者原則：不要太狠，一步一步，不要被封）**
> 1. **一次只發一支請求**，中間 sleep ≥ 5 秒；單輪偵察不超過 5 支請求。
> 2. 每輪結束**回報結果並等待確認**才進下一輪——不連環試探。
> 3. 先看 `robots.txt` 再決定要不要碰內容；robots 明示禁止的路徑**不碰**（不重蹈 Wave 5 覆轍）。
> 4. 發現任何限速/驗證碼徵兆 → **立即停手**，記錄後改用更保守策略或放棄。
> 5. 模組內預設 `request_delay` 從寬（≥ 3s），且 `--pages` 預設只抓 1–2 頁。

### 🌊 Wave 4 — 硬仗
| 順序 | 據點 | 預估難度 | 核心技術關卡 |
|------|------|----------|--------------|
| 6 | **Glassdoor HK** | 高 | Cloudflare + reCAPTCHA；疑似會對爬蟲回傳誘餌頁 |

### 🌊 Wave 5 — 合規地雷區（robots.txt 明文禁止）
| 順序 | 據點 | 預估難度 | 核心技術關卡 |
|------|------|----------|--------------|
| 7 | **獵聘 Liepin** | 極高 | 內地站反爬 + `Disallow: /*?*`。香港站不存在，價值存疑 |
| 8 | **BOSS直聘 Zhipin** | 極高 | 滑塊驗證 + `Disallow: /*?query=*`。香港站不存在 |

> ⚠️ **Wave 5 處理原則**：使用者已明確表示「8 個都做」。因此**模組照寫**，但：
> - 模組頂端設 `_ROBOTS_RESTRICTED = True`，`search()` 首次執行時 `logger.warning` 提示該站 robots.txt 明文禁止爬取搜尋頁，請自行確認合規與用途。
> - README 技術筆記中如實記載 robots.txt 限制，不掩飾。
> - 此旗標**只影響該站**，不得改變其他據點行為（鐵律 #4）。

## 二、各站作戰方案（已掌握情報 + 待驗證項）

### 1️⃣ Recruit（www.recruit.com.hk）
- **技術棧**：ASP.NET WebForms（非 MVC）。詳情頁 `/jobseeker/JobDetail.aspx?jobOrder=<ID>`。
- **搜尋機制**：`action=default.aspx`，**method=POST**。表單欄位已實測到手：
  | 欄位 | 用途 |
  |------|------|
  | `UclRespJobSearchFilterControl$keywordTxt` | 關鍵字（text） |
  | `keywordType` | 關鍵字比對方式（radio，5 種） |
  | `location` | 地區（checkbox，數量龐大 → **直接抽出建地區字典**） |
  | `jobCat` / `jobFunc` | 職能大類 / 細類（checkbox 多選） |
  | `UclRespJobSearchFilterControl$searchBtn` | 送出（submit） |
- **job_id**：`recruit::<jobOrder>`（實測樣本：`L0607911`、`E0690101`、`L0607982`、`L06062452`）
- **最大關卡**：WebForms 要求回傳 `__VIEWSTATE` / `__VIEWSTATEGENERATOR` / `__EVENTVALIDATION`。
  解法：先 GET 首頁 → 用 BeautifulSoup 抽出全部 `input[type=hidden]` → 連同搜尋欄位一起 POST。
- **備案**：若 POST 過於脆弱，改走分類瀏覽頁（如 `/GraduateJob/`，已確認存在）或 sitemap。
- **地區字典**：從首頁表單的 `location` checkbox 的 value/label 抽出，落成 `scrapers/recruit_districts.json`。
- **待驗證**：搜尋結果頁的職位卡選擇器、翻頁參數、刊登日格式。

### 2️⃣ JobMarket（www.jobmarket.com.hk）
- **技術棧**：J2EE / JSP（`index.jsp`、`.jsp` 路徑）。
- **已確認的瀏覽網址規則**（三層職能）：
  ```
  /Jobs/health-beauty-care/?ftype=0&JobFunctionID=12          # 大類
  /Jobs/account-audit/?ftype=0&JobFunctionID=1                # 大類
  /Jobs/account-audit/accountant/?ftype=1&SubJobFunctionID=2  # 子類
  /Jobs/account-audit/audit/?ftype=1&SubJobFunctionID=3
  ```
- **關鍵字搜尋網址**：首頁 form 抽取未命中（搜尋框可能是 GET + JS），**待逆向**。
- **robots.txt**：只有兩條（`User-agent: *` + `Disallow: /UpFiles/`）→ **對爬蟲極度友善**，可放心實作。
- **反爬**：首頁偵測到 Cloudflare 字串，但 296KB 內容正常回傳 → 高度疑似只是載入 CF 腳本，非真挑戰。**實測時以「能否拿到職位卡」為準**。
- **待驗證**：職位卡選擇器、翻頁、刊登日、地區體系（是否有 district 參數）。

### 3️⃣ foundit.hk（原 Monster HK）
- **品牌變更**：`monster.com.hk` → **301 → `www.foundit.hk`**。模組命名建議 `foundit`（`--source foundit`），README 標註「原 Monster HK」。
- **實測結果**：
  - `/search/jobs?q=engineer` → **403 Access Denied**（386 bytes）
  - `/search/it-jobs` → **403 Access Denied**（388 bytes）
  - `/xmlsitemap/todays-jobs-sitemap.xml` → **200（17KB）✅**
  - 另有 `https://www.foundit.hk/xmlsitemap/sitemap-index.xml`
- **雙路線作戰**：
  - **路線 A（首選）**：Playwright 真瀏覽器開 `/search/jobs?q=...`，看能否過邊緣 WAF。
  - **路線 B（保底）**：解析 sitemap → 逐筆職位頁抓詳情。優點是一定拿得到；缺點是 sitemap 只含「近期職位」，無法做任意關鍵字搜尋。
  - 若 A 失敗、B 成功：模組仍上線，但 README 註明「`--keyword` 在 sitemap 模式下改為本地過濾（先抓後篩）」。
- **待驗證**：職位頁選擇器、翻頁。

### 4️⃣ eFinancialCareers（金融專業）
- **網域**：主站 `efinancialcareers.com`（200 / 787KB），**有專屬香港網域 `efinancialcareers.hk`（200 / 70KB）**。
- **實測**：常見搜尋網址 `/jobs-hong-kong`、`/search-jobs/hong-kong` **皆 404** → 路徑規則不同，需逆向。
- **重要線索**：robots.txt 有 `Disallow: /v1` → **強烈暗示站內有 `/v1` 開頭的 API**。求職頁很可能是前端打 API 拿資料。
- **可用資源**：
  - `Sitemap: https://www.efinancialcareers.com/sitemap-secure/latestjobs/xml`
  - `Sitemap: https://www.efinancialcareers.com/us-en-jobs-sitemap.xml`
- **作戰**：Playwright 開 `efinancialcareers.hk` → 錄 Network XHR → 找出職位列表 API → 優先用 API（比解析 DOM 穩）。
- **定位**：金融 / 銀行 / 投資垂直專業站，職缺量體小但單價高，與既有五站互補性強。
- **待驗證**：API 端點、地區篩選參數、刊登日格式。

### 5️⃣ ~~HKGoodJobs~~ → **OfferToday（www.offertoday.com/hk/recommend）**
- **舊域結論（2026-09-05，已作廢）**：`hkgoodjobs.com` 全路徑 403、回應 202–210 bytes、robots 亦 403、
  TLS 憑證錯置。典型「整個站台拒絕此來源」特徵（不像 CF 挑戰會回 challenge 頁）。
- **情報反轉（2026-09-06）**：站方已轉址/更名到 **`https://www.offertoday.com/hk/recommend`**。
  `/hk/` 路徑段暗示**多地區架構**（可能還有 `/tw/`、`/my/` 等），且 `/recommend` 是推薦職缺頁。
- **待驗證清單（逐項、低速）**：
  1. `robots.txt` 是否可讀、是否禁 `/hk/*` → **決定能不能做**
  2. 首頁/推薦頁是否伺服器渲染（requests 可達？）還是需要瀏覽器
  3. 職位卡選擇器、job_id 來源、詳情頁網址規律
  4. 是否有搜尋/關鍵字、地區、分類參數
  5. 翻頁機制（頁碼參數 vs 無限滾動 API）
  6. 刊登日期格式（決定 `--days` 可行性）
- **🔬 2026-09-06 低速偵察實測記錄（3 輪，共 3 支內容請求 + 2 次單頁導航）**
  | 輪次 | 動作 | 結果 |
  |------|------|------|
  | R1 | GET `/robots.txt` | ✅ 200 / 173B，**極寬鬆**：僅禁 `/hk/scan/*`、`/en/scan/*`、`/hk/recommend?appliedJobId=*`（應徵追蹤網址）。`/hk/recommend`、`/hk/search` **明確允許** |
  | R1 | GET `/hk/recommend` | ✅ 200 / 14KB（SPA 空殼，無職位資料） |
  | R2 | Playwright 開 `/hk/recommend` | ✅ 200 / 378KB，**13 個 `/hk/job/<加密id>` 職位連結**、18 個 jobCard；**無驗證碼、無 WAF** |
  | R3 | Playwright 開 `/hk/search` | ✅ 200 / 354KB，12 個職位連結、14 個 jobCard；錄到 8 支 `wapi` |
- **已掌握的 API 與資料來源**（`https://www.offertoday.com` + `/wapi/...`）
  - `/wapi/ip/getIpLocation` → `{"chinaMainlandIp": false}`，**未被地區封鎖**
  - `/wapi/geek/recommend/filter/content/all` → 🎁 **完整篩選字典**：`POSITION` 職能樹（如 `101000` 會計，含 level/parentCode/children）
  - `/wapi/geek/recommend/getHomePopWords` → 🎁 **地區字典來源**：`locationList` 為 `{code: "sHK101101cHK101101104", desc: "上環招聘"}`（上環/鴨脷洲/香港仔/筲箕灣…）
  - `/wapi/geek/recommend/jobDetail?id=<加密id>&sessionId=...` → 單筆職位詳情 API
  - `/wapi/user/info` → `code 1002 需要登入`（**不需登入即可抓列表**，此為會員資訊）
- **身世之謎**：頁面載入 `https://static.zhipin.com/assets/sdk/apm/patas.2.1.0.min.js`
  （BOSS直聘 APM SDK）→ **OfferToday 疑為 BOSS直聘的香港站**，但**未繼承其全站安全驗證**，
  目前對自動化友善；另有 `/web/security/entry/index.js` 需持續觀察是否升級防護。
- **網址規律**：詳情 `/hk/job/<base64 加密 id>`（例 `/hk/job/0oX09OIWC7e4SaVlwt3p9Q==`）；
  導航另有 `/hk/search`、`/hk/news`、`/hk/qa`、`/hk/job-expectation`（`/hk/scan` 為 robots 禁區，**不碰**）。
- **待辦（下一輪開始）**：① 抓兩支字典端點建字典 → ② 找出職位**列表/搜尋 API**（含關鍵字、地區、分頁參數）→ ③ 卡片欄位與刊登日格式。
- **紅線**：robots 明文禁止的項目**不做**（最多警告後忽略）；觸到限速即停。

### 6️⃣ Glassdoor HK
- **實測**：`glassdoor.com` → 302 → `www.glassdoor.com.hk/index.htm`（200 / 693KB）。
- **反爬**：偵測到 Cloudflare + reCAPTCHA 字串。首次探針曾回傳可疑標題（「1,664 Carlos Alves jobs」）→ **疑似對爬蟲回傳誘餌頁**，需以「是否出現真實職位卡」驗證，不能只看 HTTP 200。
- **網址規律**（已從首頁連結證實）：
  ```
  /Job/<keyword-slug>-jobs-SRCH_KO0,<N>.htm
  ```
  例：`/Job/work-from-home-data-entry-jobs-SRCH_FW0,14_KO15,25.htm`
- **robots.txt 回 404** → Glassdoor 不提供 robots 規範，對爬蟲態度不友善。
- **作戰**：Playwright + 指紋偽裝；設定「嘗試次數上限」，過不了就誠實記載「模組已寫、實測未通過」。

### 7️⃣ 獵聘 Liepin（Wave 5）
- **香港分站不存在**：`/hk/` 回 404（4,933 bytes，標題還出現編碼亂碼，站方未處理 UTF-8）。
- **主站**：`https://www.liepin.com/` 200 / 342KB，但連線極慢（45 秒才回應）。
- **robots.txt**：
  ```
  User-agent: *
  Disallow: /user/
  Disallow: /*?*                    ← 禁止所有帶 query string 的網址（等同禁搜尋）
  Disallow: /zhaopin/?pubTime=*
  Disallow: /hunter/*
  ```
- **合規提示**：`Disallow: /*?*` 等同明文禁止爬取任何搜尋/列表結果。
- **作戰**：模組照寫，`_ROBOTS_RESTRICTED = True` 啟動警告；需 Playwright；須處理 GBK/UTF-8 編碼問題。

### 8️⃣ BOSS直聘 Zhipin（Wave 5）
- **香港分站不存在**：`/hk/` 回 404（3,567 bytes）。
- **主站**：`https://www.zhipin.com/` 200 / 512KB。已見職位頁網址 `/job_detail/8ed67996e327436603V63tq0E1NV.html`，
  以及列表 `/web/geek/jobs`、城市搜尋 `/c100010000/?query=...`（`c100010000` 為全國，非香港）。
- **robots.txt**：
  ```
  User-agent: *
  Disallow: /*?query=*     ← 明文禁止爬搜尋頁
  Disallow: /*?ka=*
  Disallow: /*?sid=*
  ```
  且明確列出 `User-agent: Jobuispider → Disallow: /`（**點名禁止招聘爬蟲**）。
- **合規提示**：不但禁 `query=`，還點名封鎖求職爬蟲，是本計畫中合規風險最高的一站。
- **作戰**：同上，模組 + 警告旗標；反爬極嚴（滑塊驗證），成功率高但需投入大量時間。

## 三、統一開發 SOP（每站七步，鐵律）

依循專案既有鐵律，每一站都走同一套流程：

1. **逆向**：找真實網域 / 跳轉規則 → 搜尋機制（表單 POST / GET / JSON API）→ 職位卡選擇器 → 翻頁機制 → 刊登日格式 → 地區篩選體系。
2. **建字典**：該站專屬地區字典 `scrapers/<source>_districts.json`；職能 / 行業若有則另建。**各站字典互不共用**（鐵律 #3）。
3. **寫模組**：`scrapers/<source>.py` 繼承 `BaseScraper`，實作 `search()` / `get_detail()`，正確設定
   `use_browser`（是否需 Playwright）與 `list_has_date`（列表是否已含刊登日，決定 `--days` 是否需抓詳情）。
4. **註冊**：加入 `scrapers/__init__.py` 的 `SCRAPERS`；`config.py` 的 `SITE_CONFIG` 補 `request_delay`。
5. **跨站隔離**：不支援的功能（`--category` / `--industry` / `--sort` / `--district`）一律
   `logger.warning` 後忽略，**不得報錯中斷，也不得影響其他據點**（鐵律 #4）。
6. **文件**（鐵律 #1、#2）：README 補「🧭 技術筆記（站名 逆向要點）」、「🗺️ 按地區篩選（站名）」、
   更新「📊 各站功能支援矩陣」、補 CLI 範例、更新路線圖。
7. **驗收 + 聚合**：通過下方驗收標準後，重跑 `python build_dashboard.py` 讓新據點進入儀表板。

## 四、驗收標準（每站皆須通過）

- [ ] 實測抓取 ≥ 1 頁，筆數 > 0。
- [ ] 13 標準欄位中，`job_id` / `title` / `company` / `location` / `url` 五項非空。
- [ ] `list_has_date` 設定正確；`--days` 行為明確（能篩則篩，不能則警告後忽略，不得靜默歸零）。
- [ ] **跨站隔離回歸**：重跑既有據點（至少 gov_hk + jobsdb），確認輸出與擴充前一致。
- [ ] 不支援的參數傳入時只 warning、不 crash。
- [ ] README 技術筆記 + 地區小節 + 功能矩陣已更新。
- [ ] 重跑 `build_dashboard.py`，新據點出現在儀表板的據點篩選中。

## 五、風險登記

| 風險 | 影響 | 對策 |
|------|------|------|
| 獵聘 / BOSS直聘 robots.txt 明文禁止 | 合規爭議 | 模組加 `_ROBOTS_RESTRICTED` 警告旗標；README 如實揭露；由使用者自行判斷用途 |
| 獵聘 / BOSS直聘 香港站不存在 | 資料與「香港求職」主旨不符 | Wave 5 才做；若實測無香港職缺，考慮標記「低價值」 |
| HKGoodJobs 可能已停運 | 白工 | 一次 Playwright 判定即止損 |
| Glassdoor 可能回傳誘餌頁 | 抓到假資料 | 以「職位卡是否真實存在」為通過標準，不看 HTTP 狀態碼 |
| foundit.hk 邊緣 WAF | 搜尋功能失效 | sitemap 保底路線（已驗證可讀） |
| eFinancialCareers 搜尋網址未知 | 需額外逆向時間 | 優先用 XHR 錄製找 `/v1` API |
| 新增據點可能影響既有五站 | 違反鐵律 #4 | 每站完成後跑跨站隔離回歸 |
